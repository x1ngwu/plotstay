## 目标和现状

目标：管理员可以对照前台栏目，在后台修改中英文内容，保存后重新打开不丢字段，预览、审核、发布与恢复历史版本都可验证。发布内容无需改代码或重启服务；三类详情布局、Lime 样式、字体和既有预订规则保持。

已核对的实现：

- `packages/contracts/src/base.ts`、`stay.ts`、`experience.ts`、`service.ts` 已定义正文、各类扩展资料、手记、图片及场次字段，数据进入 PostgreSQL 内容版本和发布快照。
- `apps/web/src/lib/admin.ts` 将三类完整资料、旅客资料、分项评分与场次以 JSON 文本框编辑。普通正文有表单，但所有类型共用大量字段，容易填错位置。
- `apps/api/src/app.ts`、`packages/domain/src/content.ts` 已有编辑权限、草稿、审核、发布、下架、恢复和编辑冲突机制。新增管理能力应复用这些规则。
- 三类详情组件仍含固定双语栏目标题、按钮、提示、空状态与地图文字；部分具体叙事内容也依赖组件默认值。仅重做后台表单不能解决这些遗漏。
- `packages/domain/src/detail.ts` 按已发布手记计算评分、分布和关键词次数；这些是计算结果。住宿人物卡另有演示统计字段，不能与内容评价统计混为一谈。
- 世界、地点和人物已有存储及引用，但当前内容后台主要选择已有项，缺少完整的维护入口；分类名称来自已有首页配置。

共用文案先限定到三类详情及其中的日期／数量选择组件；与全站共用的键按详情用途拆分，避免改详情文案意外改动首页。独立确认页、凭条模板和全站文案整体改写仍留阶段 6。文案配置按“通用详情默认值 + 类型差异”组织，不为每条内容复制整套按钮文字，不增加世界级和条目级的多层界面文案覆盖。

具体条目的故事信息归条目，例如工坊名称、地图标注和资质，不能作为通用缺省文案反复套用。评分维度可改显示名称，不能借改名改变其计算语义。价格单位、时区、可用日期和模拟行为仍由业务规则决定，改文案不改变规则。

## 后台交互

1. **内容列表与定位。** 按世界、类型、发布状态和名称查找；补齐服务端分页，不能因当前最多 200 条的限制使内容无法管理，手记和归属选择器也应能查到全部有权限的条目。进入条目后按前台栏目组织导航，标注必填、缺失、源语言和译文状态。
2. **按类型显示表单。** 住宿展示规格、亮点、睡眠、设施、房东、周边、须知等；活动展示简介、向导、步骤、集合地点、场次、须知等；服务展示项目、资质、地点、场次、须知等。相同字段使用同一组件。
3. **重复项目可管理。** 设施、步骤、资质、规则、图片等支持新增、修改、删除和上下移动；图标使用已有图标选择器。图片支持已有媒体引用或允许的地址、预览及中英说明，暂不扩展上传／裁剪／素材库工程。
4. **中英并排校订。** 桌面并排或切换查看，手机按语言切换，切换不丢输入。跨语言共用价格、图片 ID、日期及数字规格；文本分别保存，不因编辑一种语言清空另一种。
5. **场次使用日期表单。** 明确 UTC，以开始和结束时间录入；显示过期、无固定场次时的每日模拟场次说明。保留阶段 5 的计价和日期规则，不新增库存或排班系统。
6. **保存、预览与发布。** 显示保存状态、字段错误、冲突及未保存提醒；保存草稿后可在真实详情模板预览，明确预览版本与语言。预览仅授权后台身份可访问，禁止缓存和索引，不能实际创建订单。
7. **检查影响。** 发布前展示本次改动字段及缺译问题；共享资料／文案展示影响范围。能够查看历史并恢复发布，恢复后保留当前未发布草稿。

常规维护无需 JSON。已有导入和高级 JSON 能力可以保留，但与表单使用同一 schema 和保存逻辑；若保留双模式编辑，必须显式切换、校验，不能两份状态互相覆盖。

## 保存、版本与权限规则

- 表单只是编辑方式变化，不重建已有内容。未修改字段、隐藏字段、另一语言与旧版扩展都必须保留；只修改一个标题不能顺带重置价格、场次、评分或图片。
- 明确区分“没有配置／沿用默认”“主动清空”“零”和“空列表”。可选字段允许清除；必填字段拒绝空值；需要继承时提供明确的恢复默认操作。禁止用真值判断把合法的 0 或主动清空误当缺失。
- 内容正文继续整条语言回退，不逐字段悄悄混用中英文。共用文案发布必须具备所需中英值；动态数字／姓名等使用受校验的占位符，计数模板覆盖单复数，内容按文本转义显示。
- 现有条目沿用 `baseRevisionId` 与 `baseDraftToken`；新配置也要有等价的冲突检测、版本绑定审核和事务发布。失败不得出现部分语言或半份资料已发布。
- 共用界面文案由网站管理员管理；世界关联资料按世界权限管理。草稿和预览不得绕过内容归属、父条目可见性及网站强制下架规则。
- 新增共享资料维护不能直接更新当前公开字段而泄露草稿：保留稳定实体 ID，以增量版本／发布引用承载可编辑资料。分类名称沿用已有首页配置权威来源，补齐所需审核／恢复能力，不再建立第二套名称。
- 发布共享资料可影响引用它的当前页面，后台须明确提示。已有条目正文历史、历史发布记录和预订快照不能被改写；条目恢复不默默回退全世界共享资料，共享资料历史独立恢复。
- 已签发凭条继续读取原始预订快照，改名称、世界／地点、货币名称、价格或场次不能改变历史行程和金额。
- 已有稳定 ID、slug、世界归属、手记父条目等身份关系不在普通文本表单中随意变更；错误归属纠正如有需要另列方案，避免改写已应用约束。

## 实施细则与兼容要求

### 首次接入配置与旧数据

- 当前组件里的默认界面文字提取为受版本管理的初始文案，首次接入不得顺便润色。数据库配置发布后优先使用发布值；代码只保留配置尚未建立或请求失败时所需的同义兜底，正常显示的配置文字不得依赖重新构建。
- 配置初始化使用新增迁移或专用幂等增量脚本。脚本应支持只读预演，仅创建缺失的配置与初始版本，不覆盖任何已有草稿／发布，不在应用启动时自动执行，不调用全量 seed。旧世界／地点／人物资料建立初始版本时，保存原值并记录迁移来源。
- 新建表名和路由名由实施者按现有风格确定；新配置至少保留作用域、版本、语言正文、操作人、时间、当前草稿与公开引用、并发令牌和审核记录。复用公共逻辑，但不能为了套用内容表而伪造住宿／手记类型。
- 旧内容缺失新字段时仍能读取、编辑、预览和恢复。新增“主动清空”语义需兼容旧记录，可使用显式状态或覆盖元数据；不能批量改写不可变历史。无数据时保留既有栏目结构，明确显示空状态。
- 不将已拆分的字段再强行合并，例如 `hostBio` 与类型专属人物介绍目前可同时展示，应分别说明用途并保留。清单应注明 legacy 字段在哪里仍会显示，防止表单只维护新字段而遗漏展开区域。
- 列表项在中英中的对应关系必须可追踪；排序、插入和删除不得将英文步骤关联到错误图片或中文条目。实施者可采用稳定项目 ID 或明确的语言独立列表，但必须定义语义，保证旧数组兼容和未编辑语言保留，并加入相应测试。

### 预览、动态文字与权限

- 预览绑定已保存的明确版本；若译文另有修订令牌，也要绑定相应令牌，避免页面混合不同时刻的草稿。复用真实详情组件，显示预览标识；页面和数据接口都检查应用后台身份及世界权限，Nginx Basic Auth 不能替代它。
- 预览按钮禁用之外，预订 API 也只能读取当前公开内容，不接受客户端提供草稿正文、草稿价格或预览发布 ID。无公开版本的条目不能通过预览创建订单。预览中的评价默认读取已公开手记，单独预览手记时明确显示草稿且不纳入公开统计。
- 动态文案只允许注册过的键、占位符和文本；拒绝未知占位符和任意 HTML／脚本。文案清单包括浏览器侧交互、校验错误、图库及展开控件的可访问标签，不能仅替换 SSR 首屏文字。
- 可修改的栏目标识是显示文本，页面锚点、字段键、评分键与测试定位标识保持稳定。修改评分维度名称不增加或移除维度，修改单位文字不改变后端计价。
- 提交失败保留当前输入；会话失效后的重新认证流程应允许恢复编辑但重新核对权限和版本。不将敏感草稿内容放入公开 URL 或共享缓存。

## 验收标准

- **覆盖率可核对：** 字段清单中的每个可编辑数据项都有后台入口和持久化验证；只读项注明计算依据；仍在代码中的必要兜底有说明，不能留下未解释的硬编码故事正文。
- **逐字段往返：** 三类完整数据和既有手记经过读取、编辑、保存、重新打开、发布后值一致；列表顺序、中文换行、英文标点、0、空数组、主动清空、图片引用和 UTC 时间均覆盖。服务重启后仍可恢复读取。
- **真实页面链路：** 中英文各走三类“后台编辑 → 保存草稿 → 预览 → 审核发布 → 前台查看 → 恢复历史”；桌面和手机均可操作。发布内容无需构建，未发布改动不泄露到详情、列表和搜索。
- **共用配置：** 栏目标题、按钮、地图数据、评分标签和空状态均选代表项验证；改类型专用标题不影响其他类型，改共享名称能看到影响范围，无中文／英文错用或占位符丢失。
- **预览隔离：** 未授权访问拒绝；无公开可猜链接；预览不能触发真实模拟订单，页面不进入 sitemap；已发布页面和预订仍读取公开版本。
- **异常不丢输入：** 字段错误、保存失败、会话过期、并发冲突、图片失败、缺译均有明确提示；不得显示假保存成功或覆盖其他编辑者修改。
- **权限与历史：** 世界隔离、网站文案权限、审核绑定版本、下架限制、历史不可变、恢复发布均通过；共享配置和资料具有操作记录。
- **关联回归：** 改价格／场次后新预订按新发布内容计价；旧凭条逐项保持；现有手记统计只按已发布数据更新；导入、翻译任务和旧内容恢复不丢新增字段。
- **数据保留：** 仅增量迁移，不改 `001`–`006`，不重置库或重跑全量 seed。迁移前后核对原版本、发布、译文、账号、手记与订单；测试破坏性编辑在隔离 schema 中完成。
- **开发站：** 代码验证通过后按 operations.md 构建、更新并核验开发域名，保持 Basic Auth、`SITE_INDEXABLE=false`、noindex 与禁止抓取的 robots.txt。

### 保存与审核实现

- 普通栏目控件由共用契约生成，按各类型前台栏目分组。重复项目可添加、编辑、删除、移动；图标为限定枚举。图片使用共用稳定 ID，可预览地址并刷新各语言说明字段。
- 桌面并排中英，手机语言按钮切换保留未保存内容。文本列表明确按语言独立，图片文件引用、价格、数字和 UTC 时间共享。普通表单直接持有结构化状态，不通过按换行拆分的隐藏文本框往返；高级模式显式切换并校验。原高级数组编辑未改动时保留单项内部换行。
- `text.map` 承载条目地图叙事；`clearedFields` 记录主动清空，保持旧记录的原默认行为。0、空串、空数组和缺省分别处理；现有内容与译文快照没有批量更新。
- 内容列表按世界、类型、名称／slug、发布状态在服务器分页，每页 25 条，名称搜索覆盖草稿各语言。条目内手记入口带固定父条目筛选，另可从全局列表管理。后台手记仍是既有 review 内容，不提供游客评价、回复或新资格规则。
- 内容保存使用 head revision 和 draft token；界面提交审核／发布也携带令牌，阻止未看过的新译文进入审核。发布前显示相对当前公开版本的改动字段及缺译状态。冲突保留输入，可下载当前草稿副本后载入最新版本比较；会话过期可在原页面重新登录并重试。
- 共用资料草稿不会更新公开字段。审核事务内更新公开投影 `worlds.translations`、`places.names` 或 `personas.profiles`，对应历史独立保存；分类名继续使用原首页配置表，不建立第二个名称源。配置可查看／载入历史草稿，恢复发布保留当前草稿。
- 世界／地点遵循世界编辑与审核角色。人物沿用既有所有者／网站管理员权限，避免凭某个世界成员身份改写跨世界人物。全站详情文案仅网站管理员可维护；影响列表按访问权限过滤。
- 配置正文仅允许注册键、原有评分维度、纯文本与已登记占位符，单复数模板分开。最初文案从现有组件提取，不润色；同一英文词在不同中文场景的词条分别登记。新键兼容旧配置时仅做读取补全，不改写旧快照。

### 预览边界

真实模板抽到 `DetailBody.astro`，公开路由和 `/api/admin/preview/{locale}/{id}` 共同使用。后者位于现有后台 Cookie 的 `/api` 路径内，SSR 转发 Cookie 给固定内部 API，后台身份、世界、父条目及网站限制均由 API 检查。链接携带已保存 revision ID 和 draft token；译文或草稿改变后旧链接返回冲突，匿名访问返回 401。

配置预览另绑定配置 revision，验证该内容实际引用所选资料。世界名称、地点、人物、分类或详情文案的草稿只在此受保护响应中覆盖；公开页面继续读取发布值。预览为 private/no-store、noindex/nofollow/noarchive，不进入 sitemap，隐藏预订及最近凭条入口。预订 API 契约拒绝草稿正文／价格／预览参数，只从已发布内容计价。

手记单独预览显示其草稿姓名、来源、参与说明、正文、标签、星级和分项；预览不计入公开评分。三类内容预览中的手记统计仍只取已发布手记。

### 用户验收入口与操作

后台：[中文管理](https://plotstay.xingwu.dev/zh/admin)、[英文管理](https://plotstay.xingwu.dev/en/admin)。先通过既有 Nginx Basic Auth，再使用应用后台账户登录；两者仍独立。

| 类型 | 搜索 slug | 中文详情 |
| --- | --- | --- |
| 住宿 | `dockside-window` | https://plotstay.xingwu.dev/zh/worlds/lathe-worlds/stays/dockside-window |
| 活动 | `forge-walk` | https://plotstay.xingwu.dev/zh/worlds/lathe-worlds/experiences/forge-walk |
| 服务 | `augmetic-tune-up` | https://plotstay.xingwu.dev/zh/worlds/lathe-worlds/services/augmetic-tune-up |

1. 后台按 slug 搜索并编辑，沿栏目导航修改中英。设施／步骤／资质可移动、添加和删除；场次按 UTC 填写。保存草稿后“重新载入”核对输入。
2. 点击“打开已保存草稿预览”，分别打开中英链接。预览明确标示版本，不能预订；公开详情此时保持原样。
3. 检查改动字段和缺译提示，提交审核，再由管理员审核通过并发布。刷新表中详情即生效，不需要构建。
4. 从历史选择“恢复此发布”；当前草稿保留。载入旧版本再保存则追加新草稿。
5. 在条目内进入“管理此条目的手记”或“新增后台手记”，修改姓名／来源／正文／星级／分项／关键词，走同一保存预览审核流程。
6. 展开“共用详情文案与关联资料”，选择 copy/world/place/persona 或分类名称，检查影响范围，保存配置草稿。选择关联条目，打开“预览已保存配置”，检查后提交审核并发布。历史配置可独立恢复。
7. 两个标签页打开同一条目，先保存第一处，再保存第二处，应提示冲突并保留第二处输入。不要用线上重要内容做破坏性测试；自动回归已在隔离 schema 覆盖这些分支。
