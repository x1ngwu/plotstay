## 目标与边界

建立统一的语言映射、网址生成和搜索元数据规则，让首页、详情、管理页和后续新增语言使用同一套约定。内容发布、下架和译文变化应同时影响公开页面与站点地图，无须全站构建。

本项目包含语言路径调整、旧链接兼容、`lang` / `hreflang`、canonical、动态站点地图、索引控制及回归测试。继续保留 PostgreSQL → API → Astro 的边界和现有权限、版本历史、翻译任务。

本项目立项时将首页布局讨论安排在阶段 3，风格保持 digi-tech Lime。本项目不提前设计首页，也不接入真实翻译、正式内容、术语表或生产部署。正式域名和 Search Console 验证属于阶段 6；这里先完成可配置能力与本地验收，不以搜索排名或实际收录作为完成标准。

## 语言与路径约定

| 版本 | 规范路径前缀 | HTML / `hreflang` 标记 | 现有数据库与 API 语言键 |
| --- | --- | --- | --- |
| 英文 | `/en` | `en` | `en` |
| 简体中文 | `/zh` | `zh-Hans` | `zh-CN`，保留为兼容键 |
| 繁体中文（未来） | `/zh-hant` | `zh-Hant` | 启用时配置，本项目不创建内容或开放该语言 |

面向全球简体中文读者，以 `zh-Hans` 表达文字体系，不默认加入中国地区定向。URL 前缀无需与语言标记或内部键完全相同。后续增加语言通过统一语言配置表达这些映射，页面不能自行推断或硬编码中文特例。

本阶段保留已有内部键和 API 输入输出，避免为了路径改名改写不可变译文、发布快照、历史任务或导入格式。已在语言配置中增加 `path_prefix`、`language_tag`，通过共享契约 `Locale.pathPrefix` / `languageTag` 供 Web 使用。新增配置若需要数据库结构变化，使用新编号迁移，不能改写 `001`–`003` 或重置已有数据。已有中文键不应直接泄漏成新的公开路径或 HTML 语言标记。

规则如下：

1. 新生成的站内链接统一使用 `/en` 或 `/zh`；首页、详情、管理页、错误页、语言切换和分享地址共用生成规则。根路径 `/` 保持 302 到 `/en`，保留查询参数；不按 IP、浏览器语言或 Cookie 强制跳转。
2. Web 的旧中文前缀 `/zh-CN`、`/zh-cn` 及其大小写变体，对 GET / HEAD 以 308 一次跳到对应 `/zh` 地址；已知语言前缀统一小写，页面路径不带末尾斜线。组合别名与末尾斜线时也不得形成跳转链或循环。
3. 规范化只处理已知语言前缀与末尾斜线，不对世界或条目 slug 盲目转小写，不改变 API 路径或写请求。保留详情身份、管理页路径和有效查询状态；未知语言仍返回 404。
4. 语言切换保留当前世界、条目、类型和搜索词。原文回退仍按现有产品规则显示并提示；正文的 `lang` 使用实际显示语言，页面界面的 `lang` 使用界面语言。
5. 启用新语言仍须遵循现有发布要求。语言路由可用、界面字典齐全、内容已有公开译文是三个不同条件；不能用“已启用语言列表”代替内容翻译可用性。

## 公开地址与搜索元数据

以下为本项目采用的工程规范；其中官方规则依据见文末。

- 设立统一的公开站点地址配置（`SITE_URL`），与用于写请求 Origin 校验的 `WEB_ORIGIN` 分开。canonical、`hreflang`、sitemap 都基于该受信配置生成，不从任意请求 Host 或转发头拼接。正式启用索引时要求有效 HTTPS origin；域名尚未确定时可用独立测试配置验收。
- 设立显式索引开关（`SITE_INDEXABLE`），默认关闭。不能因为 `NODE_ENV=production` 就开放索引：当前构建版预览也使用这个值。开关打开而站点地址缺失或无效时应明确配置失败，不能输出错误域名或自动回退到 localhost。
- 可索引页面输出一个完整绝对 canonical，指向该语言的规范地址。中英文各指向自身，不统一指向英文；规范页面也输出自身 canonical。去除不改变内容的跟踪参数、默认参数与 fragment，但保留区分世界的参数。
- `hreflang` 使用完整绝对地址，列出该内容实际公开、可索引的语言版本，包含当前页并相互对应。禁用语言、未审译文、未发布内容与源文回退版本不得混入。英文对应页可索引时以它作为 `x-default`；没有对应英文版本时省略，不跳到无关首页。
- 标题、描述与语言标记由 SSR 输出，页面首次 HTML 即完整；不要依赖浏览器补写。语言导航与 SEO 对应关系分开：导航可以让用户进入明确提示的源文回退页，搜索标记不能把它当成译文。
- 详情页的搜索描述优先使用当前公开版本的人工摘要；摘要为空时，将同一语言正文的连续空白归一为单个空格并提取最多 200 个 Unicode 码点的片段（含省略号，较长片段优先在空格处截断）。200 是项目的自动摘要预算，不是搜索引擎限制；人工摘要不按此预算截断。源文回退仍使用实际展示的源文并保持 noindex，不读取草稿或借用其他语言的摘要。

### 页面与参数处理

| 页面类型 | 索引与地址规则 |
| --- | --- |
| 语言首页及世界列表 | 正式开放索引且主内容语言齐全时可索引。默认世界的 `world=lathe-worlds` 与 `type=all` 从 canonical 去掉；其他世界保留 `world`，避免把不同世界合并 |
| 已发布住宿 / 活动详情 | 有对应公开语言正文时可索引，使用语言前缀与稳定 slug；忽略不影响详情内容的查询参数生成 canonical |
| 搜索及类型筛选结果 | 非空 `q` 或 `type=stays/experiences` 时先 `noindex,follow`，不进入 sitemap，不输出 `hreflang` 与 canonical；未来需要独立分类落地页时另行定义，不把不同结果强行合并到首页 |
| 缺译回退或主要界面仍是后备语言 | 保持可阅读并提示，`noindex,follow`；不输出 canonical / `hreflang`，不进入 sitemap；该策略用于暂不开放索引，而非用 noindex 合并重复地址 |
| 管理、登录及未来个人凭条 | `noindex`，不输出公开语言对应关系、不进入 sitemap；权限继续由后端保证，搜索标记不能替代认证 |
| 未知语言、世界、草稿、下架内容 | 维持真实 404；API 故障维持 503，不返回带错误提示的 200。均不输出 canonical / `hreflang` 或进入 sitemap |
| 开发、预览和 dummy data 环境 | 全站 `noindex`，索引开关关闭时不输出正式 canonical / `hreflang`，sitemap 返回空 URL 集合；通过隔离测试显式打开开关验收正式模式 |

参数是否改变内容按路由定义判断。阶段 2.5 已交付的实现仅以 `world`、`type`、`q` 承载列表状态；分页已列入[阶段 3 必做项](plan.md#阶段-3-必做分页与内部链接)。最新首页方案区分发现首页与完整结果列表，建议新增结果状态、`page`、地点与类别条件；已确认增加服务类型，日期 / 数量只保存为行程意向。实施时同步扩展 URL、索引及测试规则，分别保留首页和完整列表的规范身份，纳入服务详情的语言对应与 sitemap，不能默认删除一切 query。SEO 地址清理不等于清除用户的浏览状态；新增规则已在阶段 3 实现并验收，详见[阶段 3 方案](phase-3-discovery.md)与[实际结果](development-status.md#阶段-3-实际交付与验收)。

## 动态站点地图与 robots

- 提供 `/sitemap.xml`，运行时经 API 读取可公开、可索引的内容，列出规范语言首页、世界列表及住宿 / 活动详情；覆盖全部记录，不能被当前列表接口默认 50 条截断。
- 与页面共用可见性、语言可用性和地址规则。草稿、隐藏或受限制世界、下架条目、缺译回退、搜索筛选、管理页及个人记录均排除。当前手记没有独立页面，不为其虚构 URL。
- 首期在 HTML 维护 `hreflang` 即可，sitemap 不必重复一套语言关系。若输出 `lastmod`，使用实际公开内容变更时间，不能用每次请求时间；没有可靠字段时先省略。
- 发布、下架、恢复历史发布或公开语言变化后，下次页面和 sitemap 请求就应反映新状态，无需重建或重启。API 故障返回 503，不伪装成成功的空 sitemap。
- 提供 `/robots.txt`，正式索引模式声明完整 sitemap 地址。需要抓取 `noindex` 的页面不能同时被 robots 禁止访问；不把 `Disallow` 当成禁止收录的保证。预览关闭索引仍由页面 / 响应头表达，当前 SSH 访问方式继续保留。
