## 已确认方向与本次调整

首页是一家看起来认真经营、细节带有世界观幽默的虚构旅行平台。参考 [Expedia](https://www.expedia.com/) 的头部与带背景图的搜索区，以及 [Airbnb](https://www.airbnb.com/) 的内容发现栏目；以用户描述的页面结构为依据，具体文案稍后填写。

| 事项 | 已确认决定 |
| --- | --- |
| 页面形态 | 普通网页滚动；大区块保留 digi-tech Lime 窗口式边框和细标题栏 |
| 品牌展示 | 顶栏使用图标 + `PlotStay`；图标沿飞行 / 导航箭头方向做原创、荒诞的变形 |
| 世界入口 | 品牌右侧展示 `Lathe Worlds ▾`；首发菜单只有这一世界，以后支持搜索世界并跳转 |
| 账户入口 | 右侧为成为房东、用户图标、小菜单；菜单包含语言、Help centre、成为房东、管理入口及登录后可见的退出 |
| 搜索区 | 世界背景图 + `All / Homes / Experiences / Services` 四个标签 + 随类型变化的搜索字段 |
| Services 范围 | 独立服务类型，阶段 3 支持管理、搜索与基础详情；完整详情和预约分别衔接阶段 4 / 5 |
| 行程条件 | 保存日期、人数与房间数，并带到详情；第一版不按容量 / 日历余量排除内容 |
| 账户开放范围 | 现有账号可登录管理；成为房东入口先放创作说明，公开注册与申请流程后续开放 |
| 内容顺序 | 虚构促销横幅 → 附近活动分类图标 → 世界热门活动 → 热门住宿 → 按地点的 `Stay in …` 栏目 → 三项平台卖点 |
| 地点组织 | 继续按已有地点自动组织内容；活动与住宿分别进入对应栏目，地点住宿排按地点自动生成 |
| 世界配置 | 世界背景、促销和栏目内容应可配置；后续世界管理页面可以维护，40K 文案不写死在通用组件中 |
| 完整浏览 | 首页负责发现；搜索和“查看全部”进入完整结果列表，列表承担 SSR 分页 |
| 语言与索引 | 首发中英双语；延续阶段 2.5 规范，保留超过 50 条内容仍从首页全部可达的必做验收 |

这次确认替代旧方案中的“首页本身是统一分页网格”“首屏必须出现内容卡片”和“日期、人数全部留到后续”。首屏优先容纳品牌、世界与搜索区，内容卡片按新的栏目顺序出现。旧方案的每页 24 条及桌面三列 / 平板两列 / 手机单列，只作为**完整结果列表**的初始排版建议，不限制首页横排栏目。

首发公开世界选择器只展示 Lathe Worlds。开发用第二世界继续用于隔离验证，不因测试数据存在就进入首发公开导航；以后新增公开世界时复用相同组件和接口。

## 页面结构与每块的职责

| 顺序 | 区块 | 内容与行为 |
| --- | --- | --- |
| 1 | 全局顶栏 | 图标、PlotStay、世界选择器；右侧成为房东、用户图标与菜单 |
| 2 | 世界搜索区 | 有背景图的搜索面板；上方四类标签，下方目的地、日期、人数等字段与搜索按钮 |
| 3 | 虚构促销 Banner | 标题、短说明、可选插图、一个主要行动入口；可包含适用角色及活动时间 |
| 4 | Explore experiences nearby | 一排分类图标和短名称，进入当前世界 / 地点的对应活动结果 |
| 5 | Popular experiences in … | 当前世界的活动卡片横排，标题带世界名，提供查看全部 |
| 6 | Popular homes in … | 当前世界或指定地点的住宿推荐横排，提供查看全部 |
| 7 | Stay in … | 按已有地点生成的住宿卡片排，每个标题带本地化地点名及查看全部 |
| 8 | 三项平台卖点 | 组合优惠、丰富选择、会员权益三张信息卡；每张包含图标、标题、说明与行动入口 |
| 9 | 页脚 | 产品简介、虚构旅行说明、帮助等实际可访问的入口，以及完整浏览入口 |

`Popular homes` 承担世界级推荐，`Stay in …` 承担逐个地区探索。首版默认建议减少相邻栏目的重复；内容不足时允许少量重复，不凭空填充未发布条目。未来世界配置可以指定重点地点或推荐顺序。

### 顶栏与世界切换

桌面排列示意：`图标 PlotStay · Lathe Worlds ▾ [弹性间距] 成为房东 · 用户图标 · ☰`。

- 品牌图标候选方向是“努力起飞、却有一点故障的导航箭头”，例如不对称尾翼或一根掉线；保留小尺寸可识别的主体。具体造型和 Logo 图稿尚未定稿。
- 世界选择器当前展示一个已选选项；暂不为了单一世界增加无用的搜索框。未来搜索已公开世界时仍使用此入口。
- 世界切换进入目标世界首页，清除旧地点、分类、搜索词和页码；日期 / 人数默认建议也回到目标世界的初始搜索状态。相同世界内的搜索、翻页、语言切换与详情往返则保留兼容行程条件。
- 用户图标承担账户入口，小菜单承担语言、帮助及管理等通用操作；语言选择放在小菜单中。
- 普通内容发布者的管理入口称为 `Manage my listings`；世界管理者另有 `Manage this world`。两者按实际权限出现，后者负责世界背景、横幅与栏目等配置。菜单展示不替代 API 权限检查。
- 退出仅在登录后出现，并沿用受保护的退出操作；未登录状态使用现有账号登录入口。普通访客可看帮助与创作说明，管理员登录后进入已有管理能力；公开注册、房东申请和完整世界管理界面留后续，见已确认的 Q3。
- `Offer your quarters`、`Host for the Omnissiah` 仅是成为房东的候选文案，不是确定文案；品牌、帮助和管理名称的中英版本统一在文案阶段处理。

### 带背景图的搜索区

背景图来自当前世界配置，用于建立场景感；搜索面板文字和控件保持足够对比度。四个标签位于同一面板上方，字段推荐如下：

| 标签 | 目的地 / 内容 | 日期 | 人数等条件 |
| --- | --- | --- | --- |
| All | Where to? 当前世界的地点或关键词 | 可选出行日期，允许未定 | 人数与房间数；房间数仅作用于住宿 |
| Homes | 想住在哪个地区 | 入住、退房日期 | 房客与房间数 |
| Experiences | 地区或想参加的活动 | 活动日期 | 参与人数 |
| Services | 地区与服务类型 | 希望服务的日期 / 时段 | 按服务需要填写人数或数量 |

Experiences 表达“去参与什么”，Services 表达“请人替你做什么”。例如铸造厂参观与义体检修可以分属这两类；例子只是内容方向，不是正式设定或术语。用户已选择独立服务类型，All 结果同时覆盖住宿、活动和服务；服务拥有自己的筛选与基础详情入口。

日期与数量按已确认的 Q2 保存为行程意向，随搜索、翻页、语言切换和详情往返保留，后续交给模拟预订。第一版不据此改变匹配集合或承诺可订余量。具体控件采用以下默认建议：

- 默认选择 All；目的地可留空，表示浏览当前世界。地点候选限定在当前世界，同时允许关键词搜索。
- 点击标签先切换搜索表单及所需字段；下面的首页发现栏目保持原有结构，提交搜索后进入结果列表。
- 切换类型时尽量保留兼容的地点与人数；不适用的房间数、时段等不作为隐藏条件继续提交。
- 日期先使用易操作的公历控件，世界观日期表达可在文案阶段补充。后台参数使用统一格式，不解析本地化显示文字。
- 数量只能提交有效整数，日期范围须有效；空值表示尚未选择，不能偷偷变成用户没有选择的行程。
- 搜索是实际 GET 表单；关闭 JavaScript 后仍可选类型并提交，不依赖弹层组件才能浏览结果。
- 界面用“行程条件”等自然表达呈现已选日期 / 数量，不把结果称为已验证有房 / 有余位。服务时段也是偏好；人数与房间数不推导出当前没有的容量、场次或多房型库存。

### 促销与三项平台卖点

促销横幅故意使用旅行平台的严肃促销形式，内容写成符合当前世界的荒诞优惠，例如对某类 Magos 的优惠。用户给出的折扣比例与 October 7 是结构示例，不能当成固定折扣、真实截止日或最终文案。

首版建议每个世界显示一条促销，记录双语标题、说明、图片、按钮文字与站内目标、可选适用角色、开始 / 结束时间、显示状态。没有有效促销时隐藏整块；时间若参与展示，使用明确的时区，不能每次刷新重置截止时间。

底部卖点对应“组合优惠”“丰富选择”“会员权益”三个内容位置。桌面并列、手机纵向排列，标题和文案以后按世界改写。它们和促销首版默认作为叙事与发现入口；推荐按钮指向可用的内容列表或说明页。优惠结算、积分账户、组合订单和会员资格系统并未因增加该模块而纳入阶段 3；若要影响模拟账单，在阶段 5 前另行确认。

### 分类图标与内容卡片排

- 附近活动的“附近”以当前世界 / 所选地点为范围，首版不请求真实地理位置。图标是可点击的类别入口，不是装饰性死按钮。
- 图标可先用统一风格的占位图，配可替换短名称；类别使用稳定 ID / slug，名称可翻译。空类别不生成指向不存在页面的链接，可在编辑预览中保留占位。
- 活动、住宿与服务采用共享卡片骨架。活动展示图片、名称、地点、简短特点、类别、时长与每人虚构价格；住宿展示图片、名称、地点、短卖点与每晚虚构价格。服务展示图片、名称、地点、服务类别、提供者及基础报价；初始单位建议为每次，可选时长。服务无需新增一排固定首页栏目，先通过 All / Services 搜索与完整列表发现。
- 首页卡片排在桌面支持左右浏览，手机支持横向滑动；全部卡片和链接在 SSR HTML 中存在。浏览箭头可渐进增强，键盘与无脚本场景仍有可达内容和查看全部入口。
- 首版每排数量可按素材调整；初始建议 6 条，桌面容纳约 4–5 张，手机露出下一张的一部分来提示滑动。它与完整列表每页 24 条互不绑定。
- “Popular” 首版建议使用可审查的编辑推荐 / 稳定内容顺序，不引入尚不存在的热度统计、销量或用户行为画像。自动补位使用已发布内容；人工推荐能力接入世界配置后可以覆盖默认顺序。
- 地点自动分组使用稳定的 `placeId` / 世界内 `placeSlug`，名称只用于展示。同名地点不合并；无地点内容仍能从完整世界列表进入，不因缺少地点排而丢失。
- 首页只呈现有限的地点排，默认建议先显示至多 3 个有住宿的地点；底部与相关标题保留浏览全部的入口。数据更多时仍由完整列表覆盖，不能只查询 50 条后再在前端拼栏目。
- 地点之间可重复展示相同卡片组件，不能复用上一地点的数据。发布、下架或推荐条目失效后，下一请求移除失效卡片并按规则补位。

封面优先使用公开版本的首张图片及对应语言的图片说明，固定比例防止布局移动。缺图 / 加载失败时有 Lime 风格占位，标题与链接仍完整。背景图避免挤压搜索可读性；首屏关键图片优先加载，后续卡片延迟加载。

## 发现首页与完整结果列表

首页按上面的顺序展示搜索与内容发现模块。搜索、分类图标、栏目查看全部和全站浏览入口进入共享的结果列表，结果页保留顶栏、紧凑搜索条件、结果概况、卡片和分页；促销及底部营销模块不随每一页重复出现。

完整结果列表的首版实施建议：

1. 在当前世界内应用地点、类型、类别与关键词条件；All 包含住宿、活动和服务。日期 / 人数 / 房间数作为行程状态保存，不参与本阶段的匹配过滤。
2. 以地点稳定标识排序，无地点组在末尾；组内按公开发布时间降序、内容 ID 排序。无关键词时，中英匹配集合和顺序一致；搜索匹配实际展示语言，结果可以因语言不同而变化。
3. 每页 24 条，先对完整匹配集合分页，再分组渲染。同一地点跨页时重复地点标题，所有结果共享一套页码；在数据未改变时不遗漏、不重复。
4. 后端按同样的公开状态和过滤条件返回总数、结果与分页信息，使用一致的数据快照。首页推荐条数不能充当完整列表总数。
5. 改变筛选回到第一页，翻页保留筛选与行程条件。语言切换保留世界、类型、地点、类别、搜索词及兼容的日期 / 数量；无关键词时保留页码，有关键词时回到第一页。
6. 从卡片进入详情保留受约束的返回状态；返回浏览恢复首页 / 列表、条件及页码，浏览器后退尽量恢复位置。返回参数只接受站内白名单状态，不能接受任意回跳 URL。

### URL 实施建议

继续共用现有语言首页路由，以显式结果状态区分首页与完整列表；不为每个栏目创建一套模板。下表的默认规则已实现；明确参数名和校验范围见开发交接。

| 场景 | 建议地址与规则 |
| --- | --- |
| 发现首页 | `/{locale}`；非默认世界保留 `world` |
| 完整世界列表 | `/{locale}?view=results`；非默认世界保留 `world` |
| 搜索与栏目结果 | 在结果地址上使用 `type`、`q`、`place`、`category` 等实际条件 |
| 列表分页 | 第 1 页省略 `page=1`，后续页保留正整数 `page`；结果状态仍保留 |
| 旧搜索链接 | 原有 `world/type/q` 地址继续可访问，按有效条件进入结果状态；与新生成地址的规范化规则集中实现 |
| 搜索无结果 | 合法条件第 1 页返回 200，展示清除条件与返回世界浏览入口 |
| 非法条件 | 未知世界 / 地点 / 类别 / 类型、非法页码及超出实际页数的第 2 页及以后返回真实 404 |
| 上游故障 | 返回 503 和对应语言提示 |

`Homes` 是界面名称，既有 `stays` 路由和 `stay` 内容类型保持兼容。阶段 3 增加 `service` 内容类型、`type=services` 和 `/{locale}/worlds/{world}/services/{slug}` 基础详情。日期、人数与房间数以行程参数加入共享契约，保留与展示但不用于余量筛选；解析、校验与 URL 生成统一实现，禁止静默丢掉已提交的行程。

## SEO 与语言约束

- 首页与完整结果列表分别判断索引资格，使用各自的自引用 canonical；完整列表不能因为与首页共用路由就把 canonical 指回发现首页。
- 可索引的无筛选完整列表，第 2 页及以后保留结果状态与页码，不统一指向第一页。首页保留完整列表入口，完整列表提供真实 `<a href>` 分页。
- hreflang 只关联同一世界、同一页面角色与同一页码的实际可索引语言页。默认排序与推荐选择使用语言无关的标识；不把首页和结果页相互当成语言版本。
- 非空关键词、类型、地点、类别筛选先使用 `noindex,follow`，不输出 canonical / hreflang，不进入 sitemap。携带日期 / 人数等行程条件的结果默认也按参数结果处理，避免生成大量可索引组合。
- sitemap 运行时列出可索引首页、无筛选完整列表分页及全部可索引详情；页数与发布集合一致，不受推荐数量、50 条默认限制或是否位于首页栏目影响。
- 原生 HTML 提供标题、卡片链接、分类 / 查看全部入口、语言入口与分页；禁用 JavaScript 后仍能从首页走到所有公开住宿、活动和服务。
- 世界背景的文案、促销、类别与栏目标题支持中英；公开读取只使用已审定的对应语言内容。缺译回退与 `x-default` 沿用阶段 2.5 规则，不能把回退内容声明为完整译文。
- 预览继续保持 `SITE_INDEXABLE=false`。详情搜索描述保留人工摘要优先、同语言已发布正文兜底的修复。

当前拉斯世界 seed 只有一个地点，图片多为空。首页排版预览需要多个地点、足量住宿与活动、不同长度的双语文本和可替换图片。可以增加专用演示数据；不覆盖既有编辑、不重新发布已有条目。分组、超过 50 条和边界验证优先使用隔离测试 schema。正式设定、术语表、图片与幽默文案仍在对应内容阶段审定。
