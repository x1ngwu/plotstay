# Plotstay 决策记录

记录日期：2026 年 10 月 6 日。本文保存本次讨论达成的决定，供后续开发查阅。完整产品范围和验收条件见[产品计划](plan.md)，技术结构与取舍见[架构方案](architecture.md)。本记录补充原始分享讨论，后续确认优先于原文中的早期候选方案。

## 已确认的产品决定

| 主题 | 决定 |
| --- | --- |
| 名称与产品 | 命名为 Plotstay；以虚构旅行网站为界面的 fandom 网页游戏，包含多个世界及其住宿、活动和虚构游客评价 |
| 首个世界 | 《战锤 40,000》的 Lathe Worlds，中文名固定为“拉斯世界”；详细术语与正式内容使用用户已有翻译表，稍后接入 |
| 游客侧首期范围 | 发现首页、住宿详情、活动详情、共用模拟预订与可保存凭条；管理员先维护内容，用户自助创作以后开放 |
| 可编辑范围 | 介绍、设施、须知、图片等固定字段；自由页面编辑以后再讨论 |
| 数据与维护 | 现在建立真实后端及数据库；dummy data 与正式内容使用相同接口；手工编辑和批量导入都需要支持 |
| 多语言 | 首期中文和英语同等完整支持，英文略优先；结构支持继续增加语言；正文自动翻译，允许人工校订 |
| 世界创建 | 未来允许用户创建自己的世界，可能成为付费功能；创建者管理本世界，必须服从网站管理规则 |
| 协作与历史 | 需要共同编辑、版本历史和回退；首期采用保存时的版本冲突检测，实时协作以后细化 |
| 虚构身份与评价 | 房源作者及其他用户均可创作虚构评价；一个真实用户可有多个虚拟游客身份，未来可能编辑其 profile |
| 审核 | 所有公开内容先审核；世界管理员可以审核发布本世界内容，网站管理员可以介入下架 |
| 预订记录 | 服务端保存，长期用于旅行记录、内容解锁、活动参与和评价资格；首期允许游客直接预订，未来支持绑定账号 |
| 游客记录恢复 | 凭游客会话访问自己的记录；清除或丢失游客凭证后不保证能找回，公开凭条编号不能代替认领凭证 |
| 后续内容形态 | 可以扩展媒体与内容形式；旅馆下多个房间或房型未来可能需要，当前优先级低 |
| 复制与改编 | 当前不开放复制或 fork 他人作品 |
| 美术与主题 | 首期全站使用 Cocoons 的 digi-tech Lime；沿用业务、布局和皮肤分开的结构，未来各世界可更换主题 |
| 首页布局 | 到首页开发阶段再讨论具体布局和交互；现有模板只确定美术方向与换肤结构 |

## 架构确认

在核对 `/data/apps/tomodachi` 的全站静态构建、稳定发布机制，以及 `/data/apps/cocoons-web` 的换肤实现后，形成以下方案。用户随后明确表示：“可以的，我同意这个计划。我们继续”。

- 公开内容页使用 **Astro 按需渲染**，稳定的说明页可预生成。
- 前端通过接口访问 **独立的 Node.js / TypeScript 后端**；业务权限、版本和发布逻辑由后端负责。
- 使用 **PostgreSQL** 持久化世界、内容、身份、预订、审核及任务数据。
- 自动翻译由后台任务处理，脱离网站代码构建。
- 内容审核发布更新数据库中的公开版本；代码更新沿用“构建并检查新版本，再切换上线”的流程。
- 常驻服务上线时增加新进程健康检查和流量切换；数据库与媒体位于代码 release 之外，代码回退保留新产生的数据。
- 初期可在单仓库、同域名、单机部署，公开 HTML 缓存按实际需求增加。

技术选型已经确认。具体 SQL 表名、API 路径、校验库和部署参数仍属于实施细节；当前工作区中的试写代码不自动构成新的产品决定。

## 后续补充确认

### 翻译服务暂缓配置

用户在自动翻译服务选择中明确回答：“先完成接口，服务和密钥稍后配置”。因此先实现翻译任务和适配器契约，用双语 dummy data 与测试适配器验证流程。外部服务配置前保持禁用，真实翻译接通后再验证供应商调用及术语效果。

### 文档与开发的顺序

用户要求先把已经讨论好的方案写入文档，避免后续遗忘，再 **commit、push 计划文档，然后统一进入开发**。用户同时明确：已经开发的部分保留。

本次文档提交包括产品计划、架构、决策记录和原始讨论归档。已有工程配置和部分后端实现留在工作区，后续继续完善与验证。之后若出现新的范围或架构决定，先同步对应文档，再推进受影响的实现。

### 开发阶段与 session 交接

方案文档推送后，用户确认开发顺序为：**基础工程与数据结构 → 内容管理与发布 → 发现首页 → 两类详情 → 模拟预订与凭条 → 正式内容与上线**。

用户要求将顺序及实际进度记录下来，并将在新的 session 中继续开发。[开发顺序、进度与交接](development-status.md) 作为后续更新阶段状态和接手说明的入口。当前阶段 1 尚未完成，已有未提交的工程草稿继续保留；进入阶段 3 前仍需与用户讨论首页布局。
