## 修复范围

1. **管理此条目的手记**：从编辑深链接进入带 `world`、`kind=review`、`parentId` 的世界内容列表。所属作品筛选写入 URL，刷新、搜索、分页、打开手记及返回均保留；可以解除所属作品筛选。有未保存输入时先确认离开。列表切换世界时清除旧作品归属和返回上下文。
2. **退出登录后的账号设置**：账号设置不再挂载被 CSS 隐藏的角色管理模块，使用工作台的可见登录表单；登录后仍回到账号设置。
3. **创建作品**：进入 `view=editor&new=1`，显示新建标题并定位到编辑页顶部，返回 URL 保留原列表筛选和位置。刷新可重新进入新建页；首次保存后替换为真实 `content` 链接，避免刷新再次新建。“新增后台手记”同样保留所属作品。
4. **带世界参数的面包屑**：用已授权世界的本地化名称生成导航。解析完成前使用通用“世界”提示，不把内部 UUID 当作名称。

## 加载原因与处理

原实现每次切换菜单都会进行完整页面导航。页面脚本及共享依赖下载完成后才发起身份／语言／世界请求，部分模块重复读取身份和世界；内容列表与编辑选项等待身份请求完成，设定列表、设定详情与关联选项还有额外的串行等待。

本轮保留既有页面导航和服务端权限，在文档头部使用小型初始化脚本提前请求当前页需要的数据，与 JS／CSS 下载并行。已知世界的列表、导入或设定请求可以立即开始；默认世界则在世界列表返回后开始。多个 UI 模块共享本次导航的初始响应，每个模块对同一路径最多消费一次。之后的刷新仍访问 API；任何登录、退出、保存等写请求都会清除初始化响应，未消费响应最多保留 30 秒。没有跨页面缓存私有内容，也没有放宽 Basic Auth、`no-store` 或逐请求权限校验。

内容列表不再预先请求编辑选项；进入编辑器时再按需读取。设定详情与关联选项并行载入。概览按世界读取摘要的接口数量保持现状，不能据本轮优化推断大量世界或高并发下的容量。

初始化请求消费函数一并放在头部脚本中，避免工作台壳为了使用它再等待一个共享 JS 模块。

## 测量方式与限制

通过部署服务的本机 Web 入口，登录真实应用账号后只读浏览。Chromium 1440×900、关闭缓存、20 Mbps 下载／10 Mbps 上传，分别使用本机原始时延和 CDP 增加 120ms 网络延迟。时间从导航开始算到内容可用，包含页面和脚本加载；设定页需等表单输入启用。

修复前原始记录：`/tmp/plotstay-menu-performance-before.json`。对比使用相同服务、账号、世界和测量脚本；这是诊断采样，不是统计意义上的 P95。旧脚本对角色和评价只等待标题，可能早于内容返回，因此不把它们列入前后速度比较。

修复前另做轻量读取检查：1 路连续 3 次列表请求用时 11～19ms；8 路各 3 次、共 24 次用时 13～121ms，全部 200，整体 152ms。它没有模拟独立用户、并发写入或长时间负载，不能用于承诺用户容量。
