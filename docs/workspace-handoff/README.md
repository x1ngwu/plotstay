### 运行交互草图

在项目根目录运行，另开浏览器访问输出地址：

```bash
node docs/workspace-handoff/serve.mjs
# http://127.0.0.1:4399
```

仅监听本机，结束进程即可关闭。远程工作区可转发该端口；无需接入 Nginx 或覆盖开发站。不要直接用 file:// 打开，预览消息需要一致的来源。草图入口为 [prototype/index.html](prototype/index.html)。

顶栏切换“完整规划／第一步”和示例权限。它是设计审阅控件，不是未来产品中的身份切换器。

建议走一遍：概览 → 我的作品 → 编辑月影旅馆 → 改名称 → 保存并预览 → 点击预览中的介绍 → 切换中文／英文；再查看角色、评价回复、入驻申请、世界审核。选择“普通游客”查看空状态，选择“网站管理员”查看网站审核入口。

演示只在浏览器内存里保存，刷新即重置；没有账号登录、数据库或写 API。标题、介绍、价格演示实际的本地编辑；其余表单和审核动作主要表达布局或给出提示。活动／服务创建统一进入住宿示例，它们的完整栏目由规格和既有字段清单约束。示意预览不代表重新设计前台。

## 推荐实施方向

沿用 **Astro + TypeScript + 现有 Zod 表单 + 受保护的真实页面 iframe**，只在后台增加栏目定位与选中高亮。服务端继续负责保存、审核、权限和发布。首版保存后刷新预览，不引入自动保存或自由页面搭建。

先做现有后台体验，再补世界创建、入驻和普通创作者权限。第二步的待定规则不阻塞第一步。新旧后台并存试用，用户明确确认迁移并同意退役前，不删除旧版或强制切换。工程师从 `WS-00` 开始核对基线，再按依赖领取任务；不能把示例 UI 当作真实权限实现。

## 验证与边界

本次通过 20 项原型与技术检查，覆盖 17 个主页面在 1440px／390px 下的整页宽度、编辑状态、字段定位、失败保留输入、消息校验；用现有表单做隐藏字段保留实验，并读取本机已部署服务的中英三类详情共 6 页验证定位目标。详见 [technical-validation.md](technical-validation.md)。

这些结果证明推荐路径的局部可行性，不表示新后台已经实现、接口已经联调或用户已验收。真实权限、迁移、并发、全部字段、完整手机键盘操作及前台回归属于实施任务验收。

复现（使用项目已有的 Playwright／esbuild，不安装候选框架）：

```bash
node docs/workspace-handoff/verify.mjs
# 可选：同时读取本机 4321 已部署页面，仅 GET
HANDOFF_LIVE_SPIKE=1 node docs/workspace-handoff/verify.mjs
```

运行会重写本目录的截图和 `verification.json`。只读试验需要本机服务及浏览器运行权限；不读取凭据、不调用写入接口、不 seed。完整应用构建和发布未执行，也无此需要；线上保持原版本。
