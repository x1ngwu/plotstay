# 页面与交互规格

状态：用户已认可整体设计方向；WS-00～07 已实现部署并完成技术验证，返回导航已接入，世界管理仍按模块等待用户体验。实际第一阶段入口与核对路径见[实现记录](phase-one-implementation.md)。产品规则以[主方案](../user-workspace-redesign.md)为准，第二阶段建议以[待定清单](decisions-pending.md)为准。草图不是逐字段完成的产品。

## 1. 页面骨架

- 桌面：左侧固定账号工作台导航，右侧页面标题、任务操作和内容。世界管理有自己的二级导航及“返回个人工作台”。
- 手机：顶部品牌与可横向滚动的导航，正文单列；编辑器切换“编辑／预览”，保留保存操作。草图在 760px 切换布局，正式实现以内容可用性校准，不把断点当产品规则。
- 默认聚合账号所有 persona 和世界，不设全局“房东模式／游客模式”。世界、作品、发言的上下文决定操作权限；动作附近说明本次署名。
- 中文／英文界面沿用现有语言路由。编辑正文的语言切换与界面语言、预览宽度分开；不丢未保存输入。
- 第一阶段只显示已实现的能力。没有真实未读模型时显示“待处理／最近状态”，不伪造未读红点；没有改密功能时不放无效改密按钮。
- 空状态解释下一步，加载态不伪装为空列表，错误可重试。按钮提供文字；状态不只靠颜色；错误摘要能定位字段。

### 返回与面包屑（用户反馈后的必做项）

- 每个非根页面在标题附近显示明确的返回入口，例如“返回世界管理”“返回世界内容”，手机同样可达，不要求从左侧菜单重新走一遍。
- 面包屑每一级祖先可点击，当前页仅作当前位置标记。例如：我的工作台 → 我管理的世界 → 拉斯世界管理 → 世界设定。
- 从世界内容进入作品编辑，应返回该世界内容列表；从我的作品进入则返回个人作品列表。正式实现保留世界 ID、语言、标签、筛选、页码、滚动位置和所选项；浏览器后退／前进同样恢复。
- 深链接新开页没有站内来源时，返回按钮使用明确的父级作为后备，不裸用 history.back() 跳出工作台。来源 URL 只接受允许的同站后台路径；无权限时退到可访问工作台。
- 返回、面包屑、切换新旧版与侧栏离开都要统一保护未保存输入。取消离开时保留输入与当前路由；明确放弃后才离开。世界设定、角色和审核说明等表单也要覆盖，不仅作品编辑器。
- 草图本次已补全可点击层级及返回链接，并演示“世界内容 → 作品编辑 → 返回世界内容”。草图的世界设定等占位表单尚未实现完整输入持久化；上述上下文恢复和全表单离开保护是正式实现验收要求。

## 2. 页面目录

下表 `#xxx` 仅为独立草图定位符，不要求产品使用 hash 路由。并存期保留 `/{locale}/account` 和 `/admin` 为旧版，建议新增 `/{locale}/workspace` 作为新版入口，使用 `view`、实体 ID、筛选参数形成私有深链接；具体命名在 WS-00 固化。不得把旧入口强制转到新版，见[并存与人工验收](coexistence.md)。

| 页面／草图 | 内容与主要动作 | 阶段及权限 |
| --- | --- | --- |
| 概览 `#overview` | 退回原因、继续创作、最近互动；优先展示可执行事项；新账号给角色／申请／创建世界三个起点 | 第一阶段起；新流程入口第二阶段开放 |
| 我的角色 `#personas` | 名称、头像、草稿／待审／已批准状态；创建、编辑；角色作品及发言数量可有可无，不能挡上线 | 本人账号 |
| 角色编辑 `#persona` | 中英名字与简介、既有头像；保存草稿、单独送审、审核说明；当前送审与公开版本分开 | 本人编辑；网站审核，依赖 BUG-001 |
| 我的作品 `#works` | 三类作品、世界、经营 persona、公开和草稿双状态；搜索／类型／状态／世界／角色筛选；继续编辑／看意见 | 第一阶段已有编辑授权者；第二阶段入驻作者 |
| 创建作品 `#new-work` | 世界 → 类型 → 经营 persona → 填内容；只列有资格的世界 | 按现有管理权或第二阶段入驻资格；不靠角色绑定授权 |
| 作品编辑 `#editor` | 栏目表单＋真实页面预览；保存、预览、送审或发布、历史 | 有该作品编辑权；草图实际交互以住宿为例 |
| 退回详情 `#returned` | 哪个版本被退回、具体意见、修改入口；旧公开版本说明 | 本人或授权管理者 |
| 评价与回复 `#interactions` | “我写的评价／作品收到的评价”；本人发言状态与收到回复；提供者回复的署名固定 | 本人发言／绑定提供者账号；沿用现有审核 |
| 入驻与申请 `#admissions` | 已入驻、待审／拒绝／取消、可申请世界、邀请；说明资格属于账号 | 第二阶段 |
| 我管理的世界 `#worlds` | 管理角色、世界审核状态、待办、进入世界、新建世界 | 已有管理权；新建第二阶段 |
| 世界管理 `#world` | 待办分作品、评价回复、入驻三类；世界范围固定 | 本世界相应管理权限；入驻第二阶段 |
| 世界内容 `#world-content` | 本世界所有授权可见作品、筛选；导入、翻译、共享资料、历史入口 | 保留已有管理功能 |
| 世界设定 `#world-settings` | 原世界首页、地点、共享资料、文案设置；第二阶段加创作说明与入驻方式 | 按现有细分权限；公开资料变化见 D03 |
| 成员与创作者 `#world-members` | 管理成员／入驻创作者分区；取消入驻与下架分开操作 | 管理成员仍沿用原边界；第二阶段加创作者 |
| 作品审核 `#review` | 当前公开版与固定送审版差异、完整私有预览、批准或退回说明 | 有本世界发布权；过期申请须重新打开 |
| 入驻审核 `#admission-review` | 账号、创作方向、拟用角色、申请历史；批准／拒绝 | 第二阶段，本世界管理者 |
| 创建世界 `#world-new` | 基础双语设定、入驻规则、保存／送审；草稿世界内容入口 | 第二阶段，已登录账号 |
| 网站审核 `#site` | 世界首次公开／独立角色资料／账号管理；全站限制、恢复及相关工具 | 网站管理员；世界首次审核第二阶段 |
| 账号设置 `#settings` | 真实账号信息、既有登录退出、角色管理链接 | 本人；不承诺新注册或改密系统 |

第一阶段实际“我管理的内容”列表读取所选世界的管理范围，包含手记；上表“我的作品”保留第二阶段作者任务目标，不能据此放宽普通账号权限。

网站审核和账号设置是补充草图，17 页尺寸扫描之外另核验其访问状态。大列表在正式实现中要有服务端分页，筛选条件和页码写入 URL；保存返回保留筛选、滚动位置和原选中条目。BUG-004 不只靠“滚动到表单”掩盖长页结构问题。

## 3. 编辑器

### 桌面及手机流程

桌面：页面头说明作品、世界和 persona；下方公开／草稿／待审版本；栏目导航；左侧字段、右侧预览；底部操作。长表单允许栏目独立滚动，但不要造成多个狭窄滚动区域。手机先编辑，按“预览”或“保存并预览”切换画布，点击画布栏目切回相应字段并聚焦。预览内只加私有选区，不添加公开页面菜单。

字段栏始终能访问所有栏目，即使某个可选区块在预览里为空、不渲染或无法定位。图片、设施、行程等子项以后可用稳定项目 ID 定位，第一版至少做到栏目级，不承诺任意像素或任意文字点击编辑。

| 栏目 | 住宿 | 活动 | 服务 |
| --- | --- | --- | --- |
| 基础信息 | 名称、地点、简介、标签 | 名称、地点、类别、简介 | 名称、地点、类别、简介 |
| 图片 | 图库、图片说明及引用 | 封面、行程图、图片说明 | 服务图库、项目图片及说明 |
| 介绍与专有内容 | 介绍、设施、亮点、寝具 | 介绍、时长、流程、包含项目 | 介绍、服务项目、报价范围 |
| 价格与规格 | 现有房间／人数／计价字段 | 现有时长、人数和计价字段 | 现有计价、预约字段 |
| 经营角色 | 房东及共享资料引用 | 向导及共享资料引用 | 提供者及共享资料引用 |
| 须知等 | 入住、安全、取消等既有字段 | 参与要求、安全等既有字段 | 接受服务须知等既有字段 |

完整范围必须逐项对照 [5.5 字段清单](../phase-5-5-field-inventory.md)和 [5.6 字段清单](../phase-5-6-field-inventory.md)。表格和草图是栏目示例，不允许据此删字段。对共享资料显示“编辑会影响哪些页面”，按原权限进入独立资料编辑；不能把共享 persona 简介复制成每件作品各自可随意改写的字段。

### 版本与按钮

| 状态 | 提示与行为 |
| --- | --- |
| 无改动 | “已保存草稿 v3 · 公开 v2”；预览 v3；直接预览不新建版本 |
| 有未保存输入 | “有未保存修改 · 预览仍为 v3”；提交／发布前要求先保存；离开提醒 |
| 保存中 | 防重复请求；输入不重置；以提交时的快照记录保存结果，保存期间新输入仍标未保存 |
| 保存成功 | 用服务端返回的版本及 token 刷新预览；保持栏目、语言和输入；保存不会发布 |
| 失败／过期会话 | 保留输入和旧预览，解释未生效；重新登录后先核对版本再重试 |
| 并发冲突 | 保留本地修改，展示最新版本差异；禁止静默覆盖或自动合并审核决定 |
| 预览过期／加载失败 | 明确显示旧画面身份；重新载入已保存版本；不把旧画面标成最新 |
| 待审或退回 | 展示具体送审版和意见；修改不覆盖公开版；申请替代遵循各实体规则 |
| 已公开后修改 | 保留公开版，另显示草稿；发布成功才更新公开指针 |

角色保存／重提必须执行 BUG-001 的已确认规则。作品是否允许在审时继续保存、如何替代送审，先按现有服务端实际约束展示；本轮不把角色规则自动扩展到所有实体。实现时发现需要改变作品规则，单独记录产品影响。

## 4. 权限在界面中的表达

“我的作品”表示本人创作任务；“世界内容”表示管理范围，不能混为一张无区别列表。拥有 persona 只能证明署名归属，不能显示其所绑定作品的“编辑”按钮。提供者回复与作品编辑分别判断。

| 操作 | 游客型账号 | 入驻创作者 | 世界管理者 | 网站管理员 |
| --- | --- | --- | --- | --- |
| 编辑自己的角色／游客评价 | 是 | 是 | 是 | 是；不冒充他人发言 |
| 编辑本人作品 | 第二阶段需资格 | 本世界自己的作品 | 按世界权限 | 按站点权限 |
| 发布作品 | 否 | 送审 | 有发布权才可 | 仍受世界／网站状态校验 |
| 提供者回复 | 仅绑定角色所属账号且符合当期资格规则 | 同左 | 管理角色不自动有回复权 | 不能冒充提供者 |
| 审入驻／世界内发言 | 否 | 否 | 相应权限 | 全站管理权限 |
| 审角色资料／世界首次公开 | 否 | 否 | 否 | 是 |

第二阶段普通作者资格被取消时，保留作品和历史可读入口，解释受限原因；停写提供者回复。是否允许继续保存本地／服务端旧作品草稿是 D02 的一部分，界面不能自行扩大已定规则。普通游客发言资格单独判断。

## 5. 旧功能迁移清单

| 现有入口／功能 | 新位置 | 保留要求 |
| --- | --- | --- |
| `/account?view=personas` | 我的角色 | 并存期仍开旧版；新版独立提供角色创建／编辑／头像／双语 |
| `?view=reviews`、`?view=replies` | 评价与回复相应标签 | 本人草稿、送审、退回、历史署名和回复资格不丢 |
| `?view=moderation` | 世界审核或网站审核 | 旧审核页继续可用；新版按权限和实体组织，切换不能进入无权页面 |
| `/admin` 内容搜索、编辑、预览 | 世界内容、作品编辑 | 原管理者继续能操作已授权内容；中英、三类全部覆盖 |
| 发布、下架、恢复、站点限制／解除 | 审核详情和历史／更多操作 | 必须保留；危险操作展示对象、版本和影响范围 |
| 导入预演／执行、翻译提交／任务重试 | 世界内容的管理工具 | 并存期必须保留原工具受保护入口，新版迁移方式由人工体验确认 |
| 世界首页、地点、人物、共用文案版本 | 世界设定／共享资料 | 继续遵守原所有者与站点权限；提供影响范围和真实引用预览 |
| 提供者绑定 | 世界内容的经营角色管理 | 与作品所有权分开；不能把绑定作为自动授权 |
| 普通账号创建 | 网站审核 → 账号管理 | 仍只有原授权者可用；不顺带开放注册 |
| 评价／回复隐藏、恢复、角色可用性 | 对应审核详情 | 禁止把停用角色与隐藏历史当作同一操作 |

WS-00 需把此入口级清单扩展为“旧操作 → 新入口 → 权限 → 验收用例”，结合源码确认没有遗漏。全部旧后台按[并存规则](coexistence.md)保留；复杂工具必须能从新后台找到。此表仅提议新版去向，不授权重定向、删除或退役旧版。
