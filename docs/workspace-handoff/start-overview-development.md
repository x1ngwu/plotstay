研究建议与远期能力。不要执行原 start-development.md 的 WS-00～07 重建计划。

一、先核对现状，交付一个可审阅的视觉检查点

1. 核对 Git 和未提交改动，保留已有文档及 ZIP。读取当前首页、概览请求、
   内容与版本、角色、评价／回复、世界配置的实际实现。
2. 输出简短的数据映射：每类事项的来源、本人关系、所需权限、当前动作、
   完成／转栏条件、直达目标。核对作者、创建者、保存修改者的真实含义；
   不能用管理权限、最近浏览或经营角色绑定替代任务归属。
3. 制作本机可查看的首页交互稿，使用明确标注的隔离示例，不向现用库写假数据。
   包含中英、1440px 桌面、390px 手机，展示普通作者与有协助编辑工作的管理员。
   覆盖空状态、完整栏目、长名称和多世界；演示两个范围页签切换、进入及返回。
   尚依赖第二阶段的场景明确标为规划示例，不冒充当前普通账号有真实写入能力。
4. 参考 Asana 的任务组织、Strapi 的内容行层级、Confluence 的常用空间导航，
   使用调研文档中的官方资料。字体、配色、边框、图标延续 Plotstay 已认可基线。
   列出选定的字号／字重／行高、间距、按钮和标签尺寸、页签及焦点状态，
   说明借鉴点；以带数据的效果证明可读性，不只交文字方案。
5. “我的创作／我协助编辑的”先在继续处理内部按提案出稿；明确共享世界配置、
   管理员代编的分类、默认页签和显隐建议，供这次视觉检查一并审阅。
   常用世界的记录、固定、排序和存储方案同时说明；一般技术选择自行处理。
6. 提供可打开的预览入口和截图，提出少量确实影响产品的待决项，请用户集中
   核对视觉及上述边界。等待期间继续数据契约与隔离测试准备；收到确认后，
   按下列范围完成接入、验证、部署，不把交互稿当作全部交付。
   这个检查点用于核对用户特别要求的字号、大小、交互与未定边界，
   不重复确认已有权限、审核或存档规则。独立交互稿无需重启应用服务。

二、真实页面必须落实的规则

1. 需要你处理：每条有具体主体、上下文、说明和当前可执行动作，直接定位到
   对象或带筛选的审核队列。审核和退回修改排在前面；未回复评价仍在同栏，
   标明“可回复”。暂不回复／收起提醒留远期，本轮不做。
2. 继续处理：按审阅后的两个范围组织，内部保留角色／项目／世界／互动分组。
   本人创作与本人确实保存的未完成代编修改均有可信依据；不拉入所有可管理
   内容，也不把仅打开过、仅审核过的对象当成编辑任务。完成项退出，空组隐藏，
   提供范围一致的查看全部入口。需要少量新查询或私有列表支持可一并实现，
   但不借机重做其他页面。
3. 每条清楚表达“分组＋主体＋归属＋类型／状态＋说明＋动作”。名称醒目，
   世界、关联项目与署名角色的关系明确；不用含义不明的整行元信息替代层级。
4. 去重针对具体动作及版本／发言，不按整个项目去重。同一项目的内容修改和
   评价回复可以分别出现。公开版与新修改状态同时讲清，进入后定位正确版本；
   阅读或点击不等于完成。遵守原服务端版本、审核及历史规则。
5. 互动：可回复评价与退回事项进待办；评价／回复草稿进继续处理的互动组；
   待审、通过、发布及收到回复等状态进入最近进展。排除已回复的“去回复”
   提醒，处理草稿、提交、退回后的正确转栏，历史事件带主体与实际时间。
   不伪造未读模型、事件时间或完成状态，不新增多轮留言系统。
6. 常用世界：置于快捷开始上方，支持固定与最近访问补位、去重，显示实际身份。
   无记录时整栏隐藏；加载失败不能当作无记录。明确进入世界和管理两个目标，
   使用真实可用路由并检查权限。按第一步审阅后的存储范围隔离账号，
   不因本地偏好或访问记录扩大私有世界可见性。
7. 快捷开始和最近进展保留。加号只用于真正的新建，管理列表使用导航入口。
   所有世界及新用户“去逛逛”提示随未来相应页面实现，本轮不建完整世界目录，
   也不放无效入口。普通作者写项目、入驻与世界送审等第二阶段能力不提前开放。
8. 视觉与交互：统一文字层级、行距、内边距、控件尺寸；选中、悬停、焦点、
   加载、失败、重试和完成反馈清楚。中英与手机可操作；长标题正常换行，
   不用全局裁切隐藏溢出，不把必要操作只放在悬停态。页面变更尽量限制在概览，
   若共用组件改动，验证其他工作台页面不受损。

三、工程与验证

- 保留原框架与前次加载优化。首页只取有界摘要；按服务器实际能力稳定筛选、
  排序和计数，再截取展示，不拉全量内容在浏览器中挑选。避免请求瀑布和随世界
  数量无界增长的首页请求；独立栏目可以独立恢复，导航不因加载被锁住。
- 为首页需要的缺失信息补充最小必要接口／查询；逐请求鉴权，不改变业务权限。
  如需记录个人访问或固定偏好，采用审阅后的明确方案；必要时只增量迁移。
- 保留原库、数据卷、旧后台、旧深链接与历史。不 seed/reset，不修改前台展示、
  预订、凭条，不进入正式内容填充，不安装整套 CMS。
- 写入与状态转换测试在隔离环境完成；真实开发站仅使用现有数据只读检查。
- 覆盖本人／他人、代编／仅管理／仅浏览、普通编辑者／审核者、多个账号隔离，
  以及有公开版的新草稿、回复状态转换、动作去重、历史进展、世界入口权限。
  归属无法可靠判定的历史内容记录为限制，不静默误归类或更改所有权。
- 浏览器检查中英、桌面／手机、两个页签、分组、长标题、空状态、部分失败、
  点击定位及返回、未保存保护；真实实现截图对照审阅稿。
- 与修改前同环境、同数据量、同网络条件比较进入首页与菜单切换，记录请求量
  和可操作时间；不以单次本机结果宣称公网容量。必要测试按改动范围运行，
  涉及共用权限／版本逻辑时执行标准 npm test 和 npm run test:e2e。
  旧测试数量只作历史证据，不冒充本次测试通过。

明确说明公网认证后尚未验证，不能宣称已全覆盖。

最终交付：实现范围、中文／英文入口、桌面／手机截图、关键数据与状态规则、
测试和性能对照、线上版本／服务状态、迁移影响、未完成或后续事项。

完成后供用户体验，不自动 commit/push，不启动下一阶段，不退役旧后台。
