# 世界内容与审核入口整合方案

日期：2026-10-18。核对基线：`d465bbe`，应用实现与已部署的 `216d64c` 一致。状态：方案讨论，尚未授权实施。

世界管理中的内容和审核可以由统一工作台承接。三类作品列表及已存在的评价已经可以完整覆盖；审核和公开状态操作、受限内容的详情入口、空世界、按作品查看评价以及旧链接仍需补齐。因此不能只改几个链接就认定功能无损。

本次仅检查源码、读取现用数据库汇总及执行现有只读查询函数，并编写方案。没有修改应用、迁移、业务数据或部署。数据库连接强制 `default_transaction_read_only=on`；没有运行测试种子、迁移或写操作验收。以下接口和路由名称为实施建议。

## 核对结果

| 核对项 | 事实 | 承接判断 |
| --- | --- | --- |
| 三类作品范围 | `works` 默认本人内容，`scope=managed` 包含本人作品和有世界管理／编辑权限的作品；可按世界筛选 | 世界入口带上管理范围和当前世界，列表可复用 |
| 三类作品编辑 | `readWork` 与 `writeWork` 支持合法世界成员编辑他人作品；不能更换别人的经营角色 | 原编辑能力可复用，权限与资格限制继续执行 |
| 审核和公开状态 | `works` 链接进入 `author=1` 编辑模式，其详情固定返回 `canReview:false`；旧管理详情依据世界权限返回审核能力 | 新增独立内容审核及管理详情，不能把作者编辑器当成审核页 |
| 下架和恢复 | 旧编辑器存在下架、版本历史、恢复历史发布；网站管理员另有网站限制和解除限制 | 内容审核页需覆盖公开状态管理；已公开、已下架内容都须可查找 |
| 受限或暂不可编辑作品 | 新列表会禁用编辑；部分情况下连预览也不提供，且没有独立详情按钮 | 增加有权限者可用的详情／历史入口，不能把“不可编辑”当作“不可查看或处置” |
| 空世界 | 新列表的世界选项从已有作品推导，`listWorks` 又用这些选项检查世界是否合法 | 无作品的合法世界会被误判为 `WORLD_FORBIDDEN`；统一入口前修正 |
| 评价与回复 | 现有审核页已经按世界筛选，并有批准、退回、隐藏、历史恢复能力 | 可直接作为世界发言审核入口 |
| 按作品查看评价 | 旧编辑器的关联入口携带 `parentId`；现有评价审核队列没有对应作品筛选参数 | 补充精确作品筛选，不能用标题搜索代替 |
| 旧评价维护 | 代码仍允许通过旧编辑器创建和协作编辑旧结构评价；个人评价另走作者流程 | 需要明确兼容去处，不能在整合时默默删除，也不能改成管理员可编辑个人评价 |
| 首页及旧链接 | 首页仍把作品和评价待审数合在世界审核任务里；返回路径、预取和侧栏文案也引用旧路由 | 必须同步拆分待办及更新导航，避免计数和落点不一致 |

### 对手记叫法的修正

“手记”来自旧后台对 `kind=review` 的命名，不应作为第四种作品放入新内容页。当前 67 条旧结构记录都是详情页下的评价，现有评价审核的全部列表能够找到它们。

但是，代码差异并不只有名字：旧结构评价允许世界成员协作编辑，并保留旧创建入口；个人评价有固定署名和作者专用保存流程，普通管理编辑接口会拒绝修改其正文。因此可以统一称“评价”，但不能把旧数据标记、署名或编辑权限直接改成个人评价。

## 统一后的入口

左侧“我管理的内容”继续承载服务、住宿、体验。左侧“审核管理”包含“内容审核”和已有的“评价与回复审核”；网站管理员仍可使用已有“网站管理”。

| 世界管理中的快捷入口 | 目标页面 | 默认条件 |
| --- | --- | --- |
| 内容 | `view=works` | `scope=managed&world=<当前世界>` |
| 审核内容 | 新增 `view=content-moderation` | `world=<当前世界>`，默认待审核 |
| 审核评价和回复 | 现有 `view=moderation` | `world=<当前世界>&tab=reviews`，可切换回复 |
| 设定与共享资料 | 现有世界设定 | 当前世界 |
| 导入与翻译 | 现有世界工具 | 当前世界 |
| 成员 | 现有成员页 | 当前世界 |

左侧直接打开内容页仍默认“本人内容”，管理者可切到全部可管理内容。左侧直接打开两个审核页默认覆盖本人有审核权限的世界；世界快捷入口只负责预选世界。清除筛选可以回到当前账号允许的完整范围，不能改变权限。

## 内容页的承接修改

1. 复用现有列表、创建流程和三类作品编辑器。世界入口明确传 `scope=managed`；对应说明改为当前管理范围，避免选了管理范围后仍显示“仅管理本人”的说明。新建预选当前世界，作品仍归创建账号，并选择该账号的经营角色。
2. 世界合法性从权限关系判断。管理范围的世界选项包含可管理但尚无作品的世界；这种世界返回成功的空列表，并提供合法的新建入口。无权世界继续拒绝访问。
3. 把“查看详情／历史”“编辑”“预览”“审核与公开管理”分成独立能力。被撤销经营资格、作者账号停用、缺归属或角色绑定、作品或世界被限制时，保留原本有权读取者的详情和历史入口；保存、预览、发布仍按各自规则判断。
4. 有审核权限的作品卡片及编辑页提供“审核与公开管理”，进入同一条作品的内容审核详情。普通作者或只有编辑权限的成员不显示这个入口，也不能直接调用其接口。
5. 保留正文与译文保存、送审、真实预览、翻译状态及失败重试、历史文本载入为新草稿、操作记录和未保存保护。作者编辑模式不直接开启管理审核按钮；有管理权的账号通过明确入口处理审核。
6. “恢复历史文本为新草稿”和“恢复历史公开版本”分别保留：前者进入编辑流程，后者由内容审核详情执行，不能混成一个恢复动作。

## 新增内容审核页

### 列表和详情

只包含服务、住宿、体验。支持世界、类型、名称搜索和分页；默认显示待审核，可查看全部记录。审核状态与公开情况分开筛选，公开情况至少能定位公开中、未公开、已下架和受限制的内容。待审已失效的作品给出原因和重新提交要求，不把它继续算作可批准的有效待审。

待审核和公开管理复用同一详情：展示所属世界、作者及经营角色、送审版本、当前公开版本、正文及必要译文、差异提示、历史与操作记录。详情同时给出不可执行动作的原因。需要改正文时进入原编辑器，保留返回来源。

| 能力 | 承接位置与限制 |
| --- | --- |
| 批准并发布、退回及审核说明 | 内容审核详情；世界 owner/admin 或网站管理员 |
| 下架 | 内容审核详情；沿用现有管理权限，不要求先存在新待审版 |
| 恢复历史公开版本 | 历史发布记录；沿用发布资格与网站限制校验，保留当前草稿 |
| 查看历史及审核记录 | 内容审核详情；包括不可编辑、不可发布的作品 |
| 网站限制、解除限制 | 内容审核详情中仅网站管理员可用；解除限制不自动恢复公开 |
| 编辑正文、补译、载入历史文本 | 原三类作品编辑器；保留原保存与送审规则 |
| 草稿真实页面预览 | 复用现有受保护预览；其可见世界与限制校验继续生效 |

### 查询和写入方案

建议新增独立的 `/api/content-moderation/` 查询和动作接口，复用现有审核页的布局组件和已有领域函数。现有评价／回复 API 继续服务发言对象，避免把两种版本规则混在一起。

- `scopes`：按世界审核权限提供全部可审核世界，包括没有内容的世界。
- `queue`：仅查询三类作品；先应用权限和筛选，再计数、稳定排序与分页。范围与计数由服务端计算，不能由浏览器把多个世界的局部结果拼起来。
- `records/:id`：读取审核上下文、权限、历史和可执行操作；在服务端验证实际内容类型和所属世界。
- 详情动作：复用 `reviewRevisionInTransaction`、`unpublishContentInTransaction`、`restorePublicationInTransaction` 等现有事务能力；网站解除限制沿用 `releaseSiteBlock` 的权限语义。需要新增当前版本比较时放进同一事务，避免先检查后写入的间隙。

三类作品目前按最新版本 `head_revision_id`、`draft_token` 和经营资格版本 `epoch` 审核。数据库还约束只有评价可以使用 `submitted_revision_id`。本次保持三类作品规则，不直接复制评价的“待审 A、后续草稿 B”机制，不新增这类迁移。

批准仍要求正式经营资格、启用且已批准的经营角色及必要译文。资格变化后的旧送审不可直接批准；网站或作品受限时不能发布。退回、下架和读取历史的条件与批准不同，应分别计算。用户看到的动作能力不能仅由一个 `canEdit` 或前端 URL 决定。

新动作必须校验当前账号、当前权限及相关版本。批准／退回比较固定 revision 与 draft token；下架／恢复等还比较所见公开指针和限制状态。过期请求提示重新核对并保留审核说明。请求结果不明时先读取最新状态，不自动重复写入。

## 评价和回复的承接修改

世界审核入口直接指向现有 `view=moderation&world=…`。现有批准、退回、隐藏、历史恢复、固定署名和资料审核规则继续使用。

补充“所属作品”筛选：建议 URL 和队列 API 统一使用 `entry=<作品 ID>`，替代旧关联入口的 `parentId`。服务端验证作品确实属于请求世界且当前账号可审核；搜索、数量、分页、评价／回复两个页签和返回链接都使用同一作品条件。当前网站管理的绑定页已使用 `entry` 参数，页面切换时须隔离用途，避免把绑定筛选带进无关队列。

三类作品编辑器中的“管理此条目的手记”改为“查看此内容的评价与回复”，有审核权限时打开上述精确筛选。只有世界编辑权的账号不能被送入必然 403 的审核页：公开评价仍通过公开详情查看，旧结构评价的合法协作通过兼容工具处理。

### 旧功能的兼容去处

这是本方案中需明确保留的范围：

- 67 条旧评价继续作为评价出现在审核页；不复制数据，不改写历史署名、作者或 `managed` 标记。
- 旧结构评价的创建、正文编辑、译文维护、草稿预览及历史文本载入继续由现有旧编辑器承接。建议在“世界管理 → 导入与翻译／管理工具”中提供“旧评价维护”兼容入口；审核详情对确有旧编辑权限的旧记录提供“编辑旧评价”。这不增加第四种作品类型或新的主要侧栏栏目。
- 兼容入口的筛选同时覆盖旧评价纯草稿。现有审核队列从送审或发布版本取记录，不能保证所有从未送审的旧草稿都能出现；目前现用库这类缺少队列版本的旧评价为 0，实施仍应覆盖该场景。
- 个人评价保持作者专用编辑，不把管理员审核权转换成修改他人正文的权限。普通世界编辑者也不得通过兼容入口读取他人个人评价私稿。
- 原旧编辑器还有网站管理员对评价设置／解除网站限制的能力，现有独立评价审核只提供普通隐藏和恢复。这项网站专属能力保留在受权限保护的兼容管理入口，或在评价审核详情中补齐后再移除旧入口；本方案建议先保留兼容入口。

保留上述兼容能力可以满足“不丢现有功能”。若后续希望彻底取消后台创建／代编旧评价，应作为单独的产品取舍确认；本次整合不自动包含该项退役。

## 权限和导航

| 身份 | 内容列表与编辑 | 内容审核 | 评价与回复审核 | 网站限制 |
| --- | --- | --- | --- | --- |
| 普通作者 | 本人作品；仍受资格与角色规则约束 | 无 | 无 | 无 |
| 世界 editor | 所属世界有权协作的作品及本人作品 | 无 | 无 | 无 |
| 世界 owner/admin | 所属世界作品及本人作品 | 所属世界 | 所属世界 | 无 |
| 网站管理员 | 全部管理范围 | 全站 | 全站 | 可设置及解除 |

世界卡片及内部二级导航都按具体世界展示审核入口。侧栏是否有审核菜单可复用 `canModerate`，实际请求仍逐世界检查。经营角色只能由作品所有者在允许的阶段更换；永久锁、经营资格及世界编辑／审核权保持各自独立。

导航同步范围：

1. 世界卡片、世界设定／工具／成员的二级导航改指向统一页面；新页面高亮对应侧栏，保留当前世界名称与返回世界管理入口。
2. 首页待办将三类作品审核和评价审核分开计数与生成目标；回复任务保留独立落点。数量、状态和目标使用与对应队列相同的资格判断，尤其不能把失效作品送审计入有效待审。
3. 首页常用世界的“管理”、编辑器内关联入口、旧后台的新工作台链接一并盘点。
4. 编辑详情、审核详情、语言切换、刷新、浏览器前进／后退保留世界、范围、类型、搜索、状态、页码、滚动位置和选中项；`returnTo` 只接受同站白名单页面。
5. 各独立控制器都有侧栏文案和语言刷新逻辑，必须同步新增“内容审核”，避免切换角色／评价／审核页面后菜单标签为空或状态错误。

### 旧路由兼容

先完成目标能力，再更换世界管理中的日常入口。旧 `/admin`、`/account` 依项目并存约定继续可用。旧工作台 URL 使用按类型转换或明确过渡，不能统一跳到一个列表而丢失原对象。

| 旧链接 | 处理建议 |
| --- | --- |
| `world-content`，明确为三类作品 | 转到 `works&scope=managed&world=…`，转换可表达的筛选 |
| `world-content`，未指定类型 | 转到三类作品列表，并提供当前世界评价入口；说明评价已移到独立审核，编辑者使用可访问的兼容／公开入口 |
| `world-content&kind=review` | 审核者转评价页；纯草稿／协作编辑目的转兼容维护；带 `parentId` 的链接传精确作品条件 |
| `world-review`，明确为三类作品 | 转到内容审核，保留世界、类型、搜索与相应状态 |
| `world-review&kind=review` | 转评价审核；`submitted` 映射到 `pending` 等明确对应状态 |
| `world-review`，未指定类型的混合待审链接 | 显示轻量过渡选择，提供当前世界“内容审核”和“评价与回复审核”及真实计数；不再复刻一份混合操作列表 |
| 带 `content`／`revision` 的详情书签 | 根据真实对象类型、版本和当前权限定位；个人评价、旧结构评价、三类作品分别处理，不能丢掉固定版本改开最新草稿 |

旧 `published` 仅表示内容有公开指针，新列表的 `public` 还考虑世界与网站限制，二者不能盲目等同。旧状态无法准确映射时，应展示转换提示和对应受限记录入口，或保留受保护的兼容链接；不能声称无损转换后悄悄缩小结果集。

## 实施顺序和影响文件

1. **确认方案及页面职责。** 明确内容审核包含公开状态管理；旧评价维护暂留兼容工具。按现有审核页风格给出内容审核列表与详情效果，确认后接入。
2. **补齐查询和详情能力。** 修复空世界；提供独立管理详情与动作能力；新增三类作品审核范围／队列／动作，扩展评价的精确作品筛选。复用既有权限和事务校验，预计无数据库迁移。

## 承接验收标准

| 场景 | 通过标准 |
| --- | --- |
| 列表覆盖 | 同一账号和世界，旧三类作品 ID 集合与新管理列表一致；无权世界不出现 |
| 空世界 | 世界管理入口进入成功空列表，有合法创建入口；不是 403 |
| 创建和编辑 | 预选世界正确；本人／协作编辑、经营角色锁、双语字段、保存预览和版本冲突保持 |
| 作品审核 | 审核者能批准、退回；editor 和普通作者直接访问／伪造请求均被拒绝 |
| 失效及受限 | 资格变化、角色停用、账号停用、缺归属／绑定、网站限制分别给出原因；旧送审不能误发布，历史仍按权限可达 |
| 公开状态管理 | 无待审版的公开作品也能下架；已下架作品可找到历史并按原条件恢复；网站限制仅网站管理员可处理 |
| 评价和回复 | 当前 70 条评价覆盖不回退；按作品筛选、两个页签、隐藏／恢复、固定署名及历史仍正确 |
| 旧评价维护 | 旧结构纯草稿、已发布、已下架记录均有合法入口；旧协作不丢；个人评价私稿不因兼容而扩大访问 |
| 首页和导航 | 三类审核待办数量与目标列表一致；旧混合链接能到两个审核入口，不丢固定对象或版本 |
| 并发和会话 | 他人先处理、换账号、撤权、过期页面均拒绝旧动作；审核说明与未保存输入按原规则保留或清理 |
| 语言和设备 | 中英桌面及手机均可完成筛选、详情、返回和审核；所有独立页面中的新增侧栏入口正常 |
| 访问保护 | Basic Auth、禁止索引、no-store、公开 robots 禁爬和浏览器会话错误状态码保持 |

写操作验收使用隔离库和合成数据；现用库仅做必要只读对照。先执行影响范围的领域与浏览器检查，再完成构建及发布核验；不以本次只读列表比对替代后续动作测试。
