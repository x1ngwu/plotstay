2. **启动与构建入口。** 根脚本引用的 `scripts/dev.mjs`、`scripts/build.mjs`、`apps/api/src/server.ts`、`apps/worker/src/main.ts` 等尚不存在，需要按阶段补齐或调整脚本。
3. **Astro 应用。** `apps/web/` 尚无 Astro 配置、页面、语言路由和 API 客户端，需要补齐基础结构。这个阶段只需验证数据读取，首页具体设计在阶段 3 讨论。
4. **数据库与种子。** 检查迁移草稿并验证执行；根 `db:seed` 脚本引用的 seed 文件尚不存在。准备可重复导入的中英 dummy data。

## 新 session 的首个交付目标

先完成阶段 1，按以下顺序接续已有工作：

1. 阅读本文及产品、架构、决策文档，检查 Git 状态和已有实现，明确保留的草稿与缺口。
2. 修正工程配置和依赖兼容性，梳理最小数据模型及 API 契约。
3. 验证数据库迁移，完成可重复运行的 seed。建议至少包含一个世界、两条住宿、两条活动与虚构游客手记；补充开发用第二世界和缺译等情况检查边界。
4. 启动独立 API，提供已发布世界和内容的读取能力，落实基本身份、世界权限和版本边界。
5. 接通 Astro 按需渲染与语言路由，让页面通过 API 显示数据库中的中英 dummy data；建立布局与主题分开的基础。
6. 验证数据库 → API → Astro 的真实链路，检查未发布内容隔离、语言与世界边界，以及内容更新无需全站构建。记录实际运行方式和检查结果。
7. 更新本文的阶段状态、剩余事项和下一步，再推进阶段 2。

阶段 1 的可验收结果是：**可启动的前后端与数据库，浏览器能看到经正式 API 读取的双语占位内容，基础权限和版本规则经过验证。**
